# Performance mobile homepage — 2026-10-10

Intervento solo-performance su `index.html` (nessuna modifica a contenuti, dati, DB o claim).

## Modifiche
1. `content-visibility:auto` + `contain-intrinsic-size` (stima mobile, `auto` corregge dopo il primo render) sulle sezioni sotto la piega: ricerca, proprietario-hp, video-intro, evidenza, visite-virtuali-hp, servizi, perche, testimonial, mutuo-hp, stima, drone-hp, blog, territorio, chi-siamo-hp, faq-hp, form-contatto, footer. Salta Style&Layout delle sezioni non visibili al primo paint.
2. `defer` sugli script in fondo a `index.html` caricati sincroni: `js/vendor/supabase.min.js`, `js/supabase-bridge.js`, `js/media-url.js`, `js/config.js`, `js/rig-lead-form.js`. Tutti i bind avvengono su DOMContentLoaded o a runtime: ordine preservato, nessun uso parse-time (verificato).
3. Rimosso doppio caricamento di `js/media-url.js` (era incluso due volte).
4. `decoding="async"` sull'immagine hero (LCP).

## Misura (Lighthouse mobile, throttling simulato, 5 run prima / 5 dopo, stessa macchina, server locale)
- Performance score: mediana 0.61 → 0.73
- Total Blocking Time: mediana ~761 ms → ~338 ms
- Speed Index: mediana ~2938 ms → ~2379 ms
- LCP: mediana ~5,4 s → ~5,3 s (rumore alto in lab; verificare con dati reali CrUX)
- CLS: invariato ~0.033 (cookie banner)

Nota: valori di laboratorio; i Core Web Vitals reali (CrUX/Search Console) restano da misurare.
